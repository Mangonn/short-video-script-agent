# 05 复盘

## 最难的问题

最难的是让“看起来合理的脚本”满足可验证的事实边界。仅有“支持字幕”时，模型可能添加效率数字、易用性结论或具体界面细节。第一次真实输出就出现了“新手也能上手”和未经素材说明的配音入口。检查后扩充了规则标记和用例，重新生成实际输出。另一个重点是确保超时长的修订经过 **重新估时**，以及规则检查与最终交付指向同一个 `script_id`；否则模型可能用旧检查结果给新稿背书。

## 学到的做法

将模型选择动作与程序硬性验收分开：模型看工具结果后决定检索、改稿、复查或停止，程序校验素材原文、分镜时长和同稿检查状态。每条 Trace 写明动作、参数、返回和下一步，使模型调整可以复核。离线策略适合快速覆盖异常，真实模型运行才能证明模型实际采取了这些动作。

## 已知限制与下一步

- 词面规则无法理解全部隐含事实或复杂语境，仍可能漏掉某些含蓄效果承诺；下一步引入事实声明结构化标注与人工终审。
- 字数估时不等于剪辑后的真实时长；下一步用配音语速、镜头素材长度和平台预览校准。
- 素材检索目前只匹配合成别名；下一步扩展同义词召回，并对真实素材建立版本、授权和有效期字段。
- 当前 CLI 不负责生成视频、发布或存储脚本；这些不属于本题核心链路。
